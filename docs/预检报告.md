## 1. 深度图落盘与手动控制

### 1.1 现状链路

```text
RealSense 驱动 (enable_depth)
    → sample["depth"] ndarray
    → RealsenseAgent：只编彩色 jpeg_b64（丢弃 depth）
    → RecordController：只写 cameras/<id>/<seq>.jpg
    → filter / hik_dataset：若有 depth_file 才拷 d_*.png（DCS 默认从不产生）
```

| 环节 | 路径 | 行为 |
|------|------|------|
| 驱动 | `sensors/.../realsense.py` | `enable_depth` 默认 true；可对齐彩色 |
| Agent | `sensors_dcs/agents/realsense_agent.py` | `enable_depth` 且有 depth 时编码 `depth_png_b64`（uint16 PNG） |
| 录制 | `sensors_dcs/record.py` | 彩色 JPEG + 可选 `{seq:08d}_depth.png`；index 含 `depth_file` |
| 导出 | `export/filter.py` / `hik_dataset.py` | filter 拷贝 depth；hik 写出 `d_<cam>_<i>.png` |

文档已说明：多数 DCS 包无深度（`docs/hik-dataset.md` §7.2）。

### 1.2 如何手动控制「要不要深度」

| 方式 | 能否控制 | 实际效果 |
|------|----------|----------|
| **sensors YAML** `defaults.realsense.enable_depth` | 能 | **开关深度流 + 对齐**（非落盘） |
| DCS YAML `record:` | 不能 | 无深度字段 |
| CLI / 前端 | 不能 | 无相关开关 |

相关默认均为 `enable_depth: true`：

- `configs/sensors_camera.yaml`
- `configs/sensors_cameras.yaml`
- `configs/sensors_full_cell.yaml`

### 1.3 推荐做法（现阶段）

**不需要深度（当前默认数据集路径）：**

在所用的 hik-sensors 设备 YAML 中关闭流，减少 USB/CPU 浪费：

```yaml
defaults:
  realsense:
    enable_depth: false
```

然后重启 `sensors-dcs run -c …`。

**需要深度落盘：**

当前**做不到**（仅改 YAML/前端无效）。须后续改：Agent 编码深度 → `record` 写 PNG + `depth_file` → filter 透传。在此之前不要指望 hik_dataset 产出 `d_*`。

**不推荐：** 用前端按钮控深度——录制 UI 只有开始/结束/路径，且写盘路径本身未实现深度。

## 2. 增加同步、摇操后：raw data 保存清单

### 2.1 结论（先读）

`gello_arm_sync`、`gello_arm_teleop`、夹爪 gello sync **只通过 write agent 动硬件**，**不新增** episode 字段。  
录制采样仍 **跳过** `arm_write` / `gripper_write`（`record.py` sampler）。

同步/摇操期间：运动会体现在持续采样的 **`arm_read`（及 gello）** 关节序列里；**没有**独立的指令轨迹 / phase 日志落盘。

### 2.2 Episode 目录结构

```text
<record.save_dir>/
  NEXT_EPISODE
  episode_NNNNN/
    manifest.json
    states/<agent_id>.jsonl          # 非相机
    cameras/<agent_id>/<seq:08d>.jpg
    cameras/<agent_id>/index.jsonl
```

格式：`dcs_episode_v1`。

### 2.3 按 agent 是否落盘

| kind / 配置 type | 落盘？ | 主要内容 |
|------------------|--------|----------|
| **gello** | 是 → `states/` | `joints_rad`、`joints_rad_raw`、offsets/signs、port、dry_run…；manifest 可有 `gello_calib` |
| **arm**（arm_read） | 是 → `states/` | `joints_rad` / `joints_deg`、robot_ip、mode… |
| **gripper_read** | 是 → `states/` | `position_norm`、`raw_value`、fault… |
| **realsense** | 是 → `cameras/` | JPEG + index（serial、role、宽高…）；**无深度文件** |
| **arm_write** | **是 → `states/`** | `command_joints_rad`、`feedback_joints_rad`、armed、last_ok…（长表/宽表为 `{id}.j*`） |
| **gripper_write** | **是 → `states/`** | `command_position_norm` / `command_position_raw`、last_ok… |

### 2.4 同步 / 摇操相关状态

| 数据 | 落盘？ | 说明 |
|------|--------|------|
| 同步 phase / ramp_index / 冻结目标 | 否 | 仅 Runtime + WS/API |
| 摇操 enabled / write_count / 跳变 error | 否 | 同上 |
| 夹爪 gello sync 开关与 last_norm | 否 | 同上 |
| 同步/摇操下发的命令角 | 否 | 经 `arm_write`，采样跳过 |
| 同步/摇操期间臂真实姿态 | **间接是** | `arm_read.joints_rad` 时间序列 |

与 `docs/hik-dataset.md` 一致：DCS **不录** hik_gello 式 ZMQ `action_state` / 指令日志。

## 3. 长表、宽表、网格与 hik_dataset 管线

### 3.1 阶段与产物

| 阶段 | 命令要点 | 产物 |
|------|----------|------|
| 长表 | `export-timeline`（不对齐） | `timeline_events.*`：一行一样本 |
| 宽表 asof/nearest | `--align asof\|nearest [--master]` | `timeline_aligned.*` + `match_dt` |
| 网格 | `--align grid --hz N` | 同上宽表形态，行=等间隔网格 |
| 过滤 | `filter-timeline` | `timeline_filtered.*`，`step` 0…N−1 |
| 物化 | `--materialize` / `--hik-dataset` | `export/filtered/`（类 episode） |
| hik 训练集 | `export-hik-dataset` 或 filter 带 `--hik-dataset` | `export/hik_dataset/{metadata,steps,rgb_*}` |

实现：`src/sensors_dcs/export/{timeline,filter,hik_dataset}.py`；CLI：`cli.py`。

### 3.2 正确性评估

**主路径（对齐 → 过滤 → 物化 → steps）逻辑正确**，与 `docs/export-timeline.md`、`filter-timeline.md`、`hik-dataset.md` 描述的 MVP 一致：

- 长表拆 `j0..`、相机缺文件标记、gello 标定进 meta  
- 宽表 asof / nearest / grid、`master_hz`、match 统计  
- 过滤 require / max-match-dt / trim / dedupe / step 重编号  
- hik：相机 map、优先 `arm_read` 再 gello、夹爪读数、FK→笛卡尔  

**已知缺口 / 文档不一致（不影响「常用 asof+filter+hik」主验收）：**

1. 文档提到的 `--drop-incomplete`：**未实现**（不完整行靠 filter `--require`）  
2. 宽表文档列了 `t_mono`：实现宽表侧以 `t_wall`/`t_rel` 为主；物化 `t_mono` 可为 0  
3. `hik-dataset.md` §11 仍写「默认不注入 FK → 全 0」：**过时**；§12 与代码默认 `make_hik_fk_fn()`  
4. `filter-timeline --camera-map` 在未加 `--hik-dataset` 时会被忽略  
5. `--max-match-dt`：代码按符号 `dt > max`；nearest 下大负偏差可能漏滤  

### 3.3 深度 / 写指令 / 同步摇操状态是否「穿过」导出

| 信号 | 录制时 | 导出时 |
|------|--------|--------|
| 深度 | 无 | 无法凭空生成 |
| arm_write 指令 | 跳过 | 无 |
| 同步/摇操 status | 不写 states | 无 |
| gello / arm_read / 相机 / gripper_read | 有 | 可进长表→宽表→hik |

即：**不是导出丢了，而是采集阶段就没有。**

## 4. IK / FK 与 demo_test

### 4.1 代码位置

| 角色 | 路径 |
|------|------|
| 参考实现 + 测试 | `/root/autodl-tmp/demo_test/`（`fk.py` / `ik.py` / `dh.py` / `robot_fk.py`） |
| DCS 实际依赖 | `/root/autodl-tmp/sensors/src/sensors/kinematics/`（从 demo_test 移植） |
| hik 适配 | `make_hik_fk_fn()`：rad→deg→法兰/TCP FK |
| 导出消费方 | `sensors-dcs/.../export/hik_dataset.py` → **只用 FK** |
| EC616 资源 | `/root/autodl-tmp/EC616/` 主要为 URDF/网格；运动学常数在 kinematics/`robot.xml`（EA66 系） |

### 4.2 demo_test 测什么

`demo_test/tests/test.py`（约 15 用例），核心包括：

- FK 对示教点：位置误差 **&lt; 0.01 mm**  
- IK 回环（精确种子 / 扰动 LM·TRF）  
- 软限位、RMP 兼容接口、XML/示教元数据  

运行方式（在 demo_test 仓库根）：`pytest demo_test/tests/test.py -v`（以该仓 README/文件头为准）。

### 4.3 与 hik_dataset 的关系与缺口

- 导出 **自动注入 FK**（可失败则 cartesian 全 0 + `zeros_no_fk`）  
- **IK 不参与** steps 生成（无 IK 校验写出位姿）  
- sensors / sensors-dcs **未移植** demo_test 示教毫米级回归；DCS 仅有 stub FK 与「非零笛卡尔」级烟雾测试（`tests/test_hik_dataset.py`）  
- TCP 默认约 **z=0.18 m**；工具长度不对则笛卡尔会偏（可用导出 TCP 参数校正，若 CLI 提供）  
- 建议：若 cartesian 用于训练关键路径，定期在 `demo_test` 跑 FK 示教回归，并确认 `sensors.kinematics` 与 demo_test 未漂移

## 5. hik_dataset 的 observation / action 是否正确

### 5.1 语义（与 hik_gello `steps.json` 训练布局对齐）

**observations（当前步）**

| 字段 | 来源 |
|------|------|
| `joint_position[i]` | 过滤后臂关节：优先 **arm_read**，否则 **gello** 的 `joints_rad[:6]` |
| `gripper_position[0][i]` | **gripper_read.position_norm**，否则 gello `joints_rad[6]` |
| `cartesian_position[i]` | `FK(q) @ T_tcp` → xyz + XYZ 外旋 rpy；无 FK → `[0]*6` |

**actions（i → i+1；末步置零）**

| 字段 | 来源 |
|------|------|
| `cartesian_position[i]` | `inv(T_i) @ T_{i+1}` 的相对位姿（TCP 增量）；无 FK → 零 |
| `gripper_position[0][i]` | **下一步** 观测夹爪；末步 `0` |

### 5.2 明确不在 steps 中的内容

- 关节空间 action（无 `joint_action`）  
- `arm_write` / 同步 / 摇操下发的命令角  
- hik_gello pickle 里的 `action_state`（指令缓存）  
- 图像像素（仅文件名对齐的 `rgb_*`）  
- 深度（默认无）  

### 5.3 判定

在「有 arm_read（或 gello）、有 FK、相机 map 正确、过滤步有效」前提下：

- **observation**：测得/对齐状态 + FK 位姿 → **正确**  
- **action**：相邻 TCP 相对量 + 下一夹爪 → **正确（状态轨迹语义）**  
- **不是**「摇操命令角原样进 action」；若产品期望指令监督，当前 raw+导出设计 **不满足**，需另录 write 轨迹（属需求扩展，非本管线 bug）

## 6. 风险与建议清单（仍不改代码，仅建议）

| 优先级 | 建议 |
|--------|------|
| 高 | 不需要深度时 YAML 设 `enable_depth: false`，避免空跑深度流 |
| 高 | 训练用笛卡尔：确认 FK 可用、`cartesian_source=fk`，并抽查示教/真机误差 |
| 中 | 若需要指令 imitation：规划录制 `arm_write` 命令轨或独立 action 通道（现无） |
| 中 | 修正文档：`--drop-incomplete`、§11 FK 默认、宽表 `t_mono` |
| 低 | 需要深度训练集时再立项：Agent→PNG→index.depth_file→hik `d_*` |
| 低 | 将 demo_test FK 示教回归纳入 sensors CI，防移植漂移 |
