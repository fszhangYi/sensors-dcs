## 总体思路

采用 **生产者-消费者** 模式，将数据采集、录制、可视化解耦为独立线程或进程，通过内存队列/环形缓冲区传递数据。传感器始终运行，数据持续写入缓冲区；录制逻辑根据外部信号（开始/结束）决定是否将缓冲区内数据持久化到磁盘；可视化模块则以较低频率从缓冲区采样并推送到浏览器。

```text
[传感器读取] → [环形缓冲区] → [录制线程] → 磁盘（流式写入）
                     ↓
              [可视化采样] → WebSocket → 浏览器
```

---

## 1. 传感器常开与按需录制

- **传感器驱动常驻**：单独进程或线程持续读取相机、力觉、关节角度等传感器数据，不随 episode 启停。
- **开始/结束信号**：可通过键盘、HTTP 接口等方式触发。录制线程监听这些信号，决定是否将缓冲区内数据写入磁盘。
- **可选预录（Pre-roll）**：若希望在“开始”信号前保留一小段历史数据（例如前 0.5 秒），可将环形缓冲区长度设置略大于预录时长所需容量。

---

## 2. 内存缓冲区管理

缓冲区大小取决于：
- 传感器数据率（字节/秒）
- 期望保留的最大时长（若需要预录）
- 系统内存预算

**建议采用环形缓冲区（Ring Buffer）**：
- 每个传感器维护一个定长队列，新数据覆盖最旧数据。
- 缓冲区长度 = 预录时长 × 数据率 × 安全系数（例如 1.2）。
- 若不需要预录，可仅保留最近几帧（长度=1 或 2），录制时直接消费实时数据。

**示例**：假设 4 路 RGB 相机（1080p@30fps, 每帧约 6MB），总数据率 ≈ 720 MB/s。若预录 1 秒，则需要约 720MB 内存——这显然过大。因此通常会对图像进行压缩（如 JPEG/PNG）或降低分辨率/帧率，或仅预录关键帧。实际中需权衡。

**更实用的做法**：
- 录制时直接消费实时数据，不保留历史（缓冲区长度=1~3）。
- 若必须预录，只预录低频状态数据（关节角、位姿），图像不预录，或仅保留最近几帧图像。

---

## 3. 流式写入磁盘

避免等 episode 结束后统一写盘，采用 **边录边写** 的流式策略：

- **格式选择**：
  - **自定义二进制格式 + 索引**：灵活。

- **异步写入**：
  - 录制线程从缓冲区取出数据后，立即序列化并写入文件，不阻塞传感器读取。
  - 可使用双缓冲或队列解耦：传感器线程 → `queue.Queue` → 录制线程写入。
  - 磁盘 I/O 瓶颈时，可增加写入队列深度，或使用内存映射文件（`mmap`）。

- **分片与压缩**：
  - 按时间或大小将数据分片（例如每 1 分钟或每 500MB 一个文件），便于管理和传输。
  - 图像数据建议在录制线程中实时压缩（如 `cv2.imencode('.jpg', img)`），降低磁盘和内存压力。

---

## 4. 实时可视化到浏览器

- **采样频率**：可视化不需要全帧率，通常 10~20Hz 足够，大幅降低网络和渲染负载。
- **通信方案**：
  - **ZeroMQ + WebSocket 桥接**：若已有 ZMQ 生态，可通过桥接服务转发。

- **数据格式**：建议发送压缩后的图像（JPEG base64 或二进制帧）和轻量状态数据（JSON）。
- **前端渲染**：
  - 图像：使用 `<img>` 标签更新 `src`，或通过 Canvas 绘制。
  - 状态曲线：使用 Plotly.js、Chart.js 或 ECharts 动态更新。
- **独立进程**：可视化采样和发送应在单独进程中进行，避免影响采集和录制性能。

## 推荐技术栈

| 模块         | 推荐方案                                                                 |
|--------------|--------------------------------------------------------------------------|
| 传感器读取   | 独立 Python 进程（多线程）                                  |
| 内存缓冲     | `collections.deque`（定长）或 `ringbuffer` 库                            |
| 录制与流式写盘 | 自定义二进制 + 多线程异步写           |
| 开始/结束信号 | 键盘监听（`pynput`）、HTTP API（FastAPI）         |
| 可视化传输   | WebSocket（Python `websockets` + JS）                     |
| 前端展示     | Vue/React + three.js / plotly.js / 原生 Canvas                          |

## 实现步骤摘要

1. **启动传感器读取线程**：持续将数据（带时间戳）放入每个传感器的环形缓冲区（或队列）。
2. **录制控制线程**：监听开始/结束信号，开始时创建文件/话题，并启动一个消费者线程从缓冲区取数据流式写入；结束时关闭文件，停止消费者。
3. **可视化线程**：以固定频率（如 15Hz）从缓冲区采样最新一帧（图像压缩、状态打包），通过 WebSocket 广播。
4. **主进程**：负责协调各线程，处理退出和异常。

---

## 注意事项

- **时钟同步**：所有传感器数据应打上统一时钟的时间戳（如 `time.time()` 或 ROS 时间），便于后续对齐。
- **背压控制**：若磁盘写入速度跟不上数据产生速度，需丢弃旧数据或降低采集频率，避免内存无限增长。
- **进程隔离**：如果传感器驱动占用 CPU 高，建议将可视化放在独立进程，甚至另一台机器上。
- **资源监控**：长期运行时监控内存、磁盘 I/O，防止泄漏。

以上架构可以满足你“传感器常开、按需录制、流式写盘、实时可视化”的全部需求，且各部分解耦，易于扩展和维护。
